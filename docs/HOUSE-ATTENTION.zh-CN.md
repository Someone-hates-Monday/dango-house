# 互动对象与真实模型回复 · 0.5.0-alpha.7

## 为什么接上 API 仍像固定剧本

本次核对的最近 35 条角色消息均标为 DeepSeek 模型产出，没有完全相同的重复文本。问题不只是 API 是否连通：旧提示要求摸头、投喂、夸奖也必须有两三人接话；单人回答还会被追加一次“补同伴”请求。固定 CP 取向、旧演示事件和私聊提示内的现成回应又让输出反复落进留座、分饭、害羞等桥段。

另有模型动作工具靠近同伴时附赠固定回应的路径，这条路径在 API 模式下已关闭。离线演示、用户自己配置的提醒和隐藏录制入口仍允许本地台词。

## 新边界

- 摸头、投喂、喜爱、私聊入口等默认面向用户；被选中的角色先回应，单人回复有效，不强制补第二个人。其他角色可有相关的轻微回应或无台词表情，不应抢成 CP 剧情。
- 普通聊天默认回应用户。明确要求她们互相交流、结伴去窗边，或自主生活、拜访、同伴故事，才使用同伴场景。保留接话、走近与共同目的地；用户互动不会因第二个人发言就自动走过去贴另一人。
- “允许百合”是情境许可，不是每次互动的目标。用户方向事件不提供两人互相亲密的 CG；模型误提此类有效素材时舍弃 CG，保留回复。单人／多人面向用户的 POV 仍依相处模式和素材参与者验证。
- 不把本地或来源不明的旧角色台词继续喂给模型。保留可见历史和用户消息；共同事件只取已完成的模型互动。私聊提示移除现成同伴回应。
- 迷你小屋与独立私聊记录显示 `AI` / `本地` / `历史`。AI 标签悬停显示实际后端；旧记录不追认成模型输出。流式生成中的后端信息在完成后补齐。

自然语言中的互动对象目前通过事件类型和少量明确用语判断，不是完整语义分类器。复杂或相互矛盾的要求仍可能误分；模型具体措辞也具有随机性。后续可在结构化场景意图中进一步表达“谁对谁”，避免不断加角色台词模板。

## 验证

- 139 项单元测试通过，覆盖单人回应不补同伴、用户／同伴意图、选中者先发言、CG 对象、旧脚本上下文隔离、私聊不夹带固定回应，以及 API 动作不附赠固定同伴台词。
- `scripts/verify-house-ai.mjs`：隔离 SSE 服务走真实渲染器、IPC、密钥保存与 provider 路径；失败连接保持演示，成功连接后摸头只需一人回答，投喂及私聊隔离正常，聊天显示 AI 来源。
- 保存的 DeepSeek 连接实测摸头、投喂、Claude 私聊入口，以及明确要求 DeepSeek/Claude 互相聊。前三者先回应用户；最后一项多人接话；四项无接口错误。使用应用正常解密路径，没有导出 API Key，未将实际对话或用户存档提交仓库。

此修复不改视频素材、动画控制器或窗口尺寸机制。源码与本机桌面版为 0.5.0-alpha.7；公开 GitHub Release 与本机打包是不同步骤。
