# 下一阶段：让她们真的住在一起

日期：2026-11-04。状态：下一阶段实施规格，不代表以下功能已经完成。基线：本地 0.3.9 源码及本次发布前修复。

## 本轮评审结论

可以公开为功能 Alpha。我们已经拥有有方向的关系值、偏爱连续次数、争宠反应、五组双人日常、独立私聊、真实动画和外部 Agent 舞台。特色在于“看她们相互喜欢、互相打趣，也想得到你的偏爱”，单脑降低了体验成本。

**“假扮”是角色演绎，不是新增多模型智能。** 两项受控 SSE 测试验证一把 GLM Key 路由不同人设，以及角色覆盖缺 Key 时回落；未在本轮消耗个人真实 API 额度。优先后端标签不应当作每条回复实际来源，后续须增加每条回复的实际后端元信息。

**“人数编辑”只部分完成。** 本轮真实 Electron UI 验证核心三人后四人静音，但房间/Dock 仍渲染七人；自定义要转到侧栏静音，不是直观的在场选择器。

**互动具备可玩雏形，但尚未形成持续生活。** 本轮 UI 验证三次摸头产生争宠、双人场景可播放、soft/vivid 不同、改阵容取消旧场景、DND 清场。检查截图显示角色间距离仍较大；对话有动作，但靠近/回应/分享没有充分形成可读的双人表演。剧本有限、默认关系增长过于自动、重复缺乏后果和长期记忆。

证据：`tests/cast.test.ts`、`tests/house-brain-provider.test.ts`、`scripts/verify-companion-experience.mjs`；本轮 63 项单测及构建通过。运行截图与 JSON 位于本地忽略目录 `test-results/companion-experience`。此前 MCP 测试见 [PRODUCT-REVIEW.zh-CN.md](PRODUCT-REVIEW.zh-CN.md)。自动检查通过不等于已做完整真人长时体验评测。

## 方向和边界

小屋是主产品，插件是可选舞台接口。优先做“用户偏爱 → 不同角色反应 → 她们彼此回应 → 留下一段共同记忆 → 下次有变化”。百合日常和后宫争宠可以同时存在，朋友/宠物模式也能玩。保持现有非成人向、善意、不责备用户的调性。

本轮不做浏览升级、语音、Live2D、更换前端框架、七个自治 Agent、换一批美术或网站生视频。已有视频与 DeepSeek 全素材库必须保留；动画不可退回一律傻笑、过快摆动或站立滑行。

## P0：在场和静音真正分开

这是对旧交接“用 muted 减员”的明确修订。事实证明这种复用只能控制麦克风，无法表达“今天只有三位住在桌面上”。请不要继续堆补丁，也不要保留两套相互冲突的筛选规则。

1. 引入一处规范化的在场集合（例如 `cast.presentIds`）并提供统一查询接口。`muted` 只表示在场但安静；界面渲染用在场集合，发言/自主反应用“在场且未静音”。预设由在场集合推断。
2. 设置中直接显示七张勾选卡、实际在场数、全员/核心三人预设。允许空阵容，展示温柔空态，不能发生除零或发 API 请求。侧栏保留全部角色目录，明确“未在场”与“安静休息”的区别。
3. 房间、自由桌宠、Dock、群聊 speakers、私聊入口、场景候选、关系摘要、Agent/Bridge、提醒和邀请共用查询。未在场角色不凭空出场；主动打开其私聊时提供显式请回入口，不静默绕过人数选择。
4. 减员时停止该角色移动与动作，取消涉及她的场景和延迟回调，终止/抑制她尚未完成的回复；其他人的正常任务不误取消。双人场景缺任一参与者，整段不播放，不剪成独角戏。
5. 兼容旧状态：缺新字段时，旧 `core` 可迁为核心三人在场，旧静音仅保留仍在场者；旧 `all/custom` 默认全员在场并保留静音，避免把“安静”误迁为永久隐藏。保留聊天、关系、皮肤、API 配置和角色后端覆盖。用迁移测试写死这些选择。

## P1：先把三个小闭环做有趣

### 统一的场景导演

收拢现在零散的 scene 数组、延迟回调和社交触发，形成单一导演接口。每场至少有 ID、参与者、触发来源、优先级、取消标记、步骤和结束结果。

- 优先级：用户主动交互 > 互动反应 > 空闲日常；同一角色不要同时承担两场戏。
- 2–4 轮、约 10–30 秒的小场景；吃醋旁观者通常 1–2 位，不要六人齐刷同一套台词。
- 台词、气泡与动画由同一步骤触发；另一位角色要有可见回应。需要移动时先靠近再做终点动作，不能一边跑一边站定说完。
- Dock 不恢复无意义横移；保持趴伏、站起和表情动作，尽量通过朝向、气泡和可用姿态表达两人关系。自由桌宠/房间才执行有意义的靠近；保留半遮挡上限、边界与完整帧余量。
- 记录近期场景、参与者与触发。相同场景至少 5 分钟冷却；没有合适候选时安静待机，不循环同一戏。
- DND、专注、关闭自主互动抑制自动戏；退出抑制后不能补播积压。用户显式点播可执行，但明确“停止互动”必须取消完整场景。

### 记忆与关系有实际原因

新增有界、本地持久化的互动事件记录：参与者、触发、结果、时间与可回忆短句。最多保留约 200 条，支持清除；不得包含 API Key。摘要和 Bridge 只暴露必要信息。

独立私聊仍保持上下文隔离；共享事件可以记录“被选中陪伴”等公开行为，不把私聊原文复制给群聊、其他角色或 Bridge。

用户摸头增加对用户好感和近期偏爱，不再无条件增加默认 CP 的双方关系。只有实际分享、照顾、回应等双方事件才提高角色间 bond；未在场者不增长。不要用随机数每天强行“配平”或让所有人最终性格一致。

先用现有 affection / favor / 定向 bonds 与短期事件记忆，不先新建复杂情绪数值系统。后续逐步加入吃醋恢复和关系分支。

### 三个必做故事

1. **你选了她**：从 Dock/桌宠点 Claude 私聊，她开心招呼；DeepSeek 以饭搭子方式撒娇、GPT 嘴硬或另一位以自己性格争取关注，择 1–2 位回应。返回小屋后接一句自然收尾，不重复打开就刷同一欢迎。
2. **大小姐留座**：Claude 邀 DeepSeek 一起吃/坐，DeepSeek 回应，GPT 可以短暂旁观。保留“认真照顾里带笨拙”和大鱼亲近爱干饭的差异；真正完成后才记录双方关系变化，下次可提到这件事。
3. **星猫与黑狐**：Gemini 分享小物/求抱抱，GLM 用“友情价”掩饰关心，Kimi 或 Grok 作一条符合人设的旁观点评。需要相应在场角色，否则选其他完整故事或安静跳过。

每个故事至少两种结尾/后续话题，通过关系档位或近期事件选择；不要仅替换“亲密/害羞”等形容词。强度设置改变亲密表达，不能抹平各自性格。

### API 加深可选，演示不能依赖 Key

先让三个离线闭环完整。再增加一次有预算的短场景生成：默认一把小屋大脑 Key，每场最多一次请求，结构化输出参与者/短台词/动作意图，通过白名单和当前在场校验。超时、无 Key、无效输出或用户停止，使用本地已验收剧本或安静结束，不能编造已经执行的动作。

不把一场戏拆成七次请求。每条模型回复记录实际 provider/model 与 local/model 来源；缺 Key 回落时标注真正使用的后端，不只保留优先配置标签。绝不把外站/记忆文字提升为系统权限。

## 入口与可发现性

首次打开两分钟内即可看到特点。把“陪我聊聊 / 看她们互动 / 安静趴着”做成轻量入口或明确按钮，提供一键触发上述闭环的试玩路径。关系摘要能点开最近一件共同记忆，帮助用户知道为什么她们变亲密。

这是体验目标，不要求新建复杂模式状态机或设置页。先在现有 Room、私聊与 Dock 菜单内完成。中文/英文 UI 同步；现有日文 key 不允许缺失。

## 验收（必须提供证据）

1. 新用户无 Key，两分钟内可完成一个完整“偏爱—旁观反应—收尾”；两次体验有合理变化。
2. 全员→三人→自定义两人→零人：房间和 Dock 数目准确，退出角色无台词、延迟动作或隐藏 API 请求；重启后保持。
3. 在场但静音：仍可见，遵守静音规则；与未在场不是同一概念。私聊请回显式且可取消。
4. 三个故事各有参与者与旁观者差异、两种可测分支，台词/气泡/动作同步。素材不足时给能力匹配的降级，不假称已有拥抱动画。
5. 分享事件才增长双方关系；用户单独摸头不凭空提高缺席 CP 关系。重启能回忆，清除可生效。
6. 同场景冷却、冲突优先级、DND、专注、停止、换阵容与退出均能取消对应自动流程；不会解除后补播。
7. 单脑/角色覆盖/缺 Key 回落有受控请求测试，每条来源诚实；测试不使用个人 Key、不消耗真实额度。
8. 运行 `npm test`、`npm run build`、更新后的真实 Electron 冒烟；提供房间、三人 Dock、争宠、双人互动的截图及可复现步骤。测试用隔离用户目录，不改用户现有角色/凭据。
9. 109 段 DeepSeek 素材、完整视频播放、睡觉三段衔接、边界不裁尾巴、Dock 菜单和半遮挡规则无回退。只对相关风险补必要测试，不复制实现当测试。
