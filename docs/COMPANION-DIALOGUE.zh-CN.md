# 陪伴对白设计与模型接管 · 0.5.0-alpha.8

## 问题与目标

普通摸头后的“别碰掉我的书”、赞美后的否认、投喂后的条件句，会让善意互动像被纠正。根因之一是将“被打扰会不满”“傲娇”“收费玩笑”等特征写成常态，模型便把它们当作每次都应表演的台词结构。仅删除某句文本无法解决这一类问题。

现在的目标是：先理解本次互动和当前话题，由模型生成自然回应及匹配动作；人设指导表达方式，情节由当前情境推动。普通善意互动允许直接开心、享受和接受，不需要“先拒绝、再嘴硬接受”的后半句。明确不适时仍能温和表达边界，不把真实拒绝解释成欲拒还迎。

## 公开方案参考

[Kindroid 的人格定制文档](https://kindroid.ai/v2/docs/customizing-personality/)区分人格、简短回复指引、记忆和示例。其说明强调正向、准确的描述，并提醒常态指令与条件指令会产生不同效果：把一种偶尔的表现写成命令，可能每次都执行。我们据此把冷艳落实为沉着简练，把温柔落实为接住对方，而非不断要求模型“拒绝后接受”。

[SillyTavern 的角色设计文档](https://docs.sillytavern.app/usage/core-concepts/characterdesign/)区分人物事实、情境、示例对话、历史及补充指令，并提醒长期设定和示例都会占用上下文。我们采用有限的角色示例，而不是把整个离线动作剧本加入提示或逐句复播。

以下是本项目依据这些公开设计作出的实现选择，不是厂商私有提示词或对效果的保证。

## 实现层次

1. **人物事实**：`src/shared/characters.ts` 保留外观、兴趣与关系；删除 Claude 默认因打扰表达不满的设定，调整 GPT 含蓄与 GLM 玩笑的触发范围。
2. **表达指引**：`src/shared/companion-voice.ts` 集中七位角色的语气与关心方式，以及朋友／宠物／亲密模式下的共同表达原则。公共小屋与单独聊天使用同一份指引。
3. **事件情境**：摸头、投喂、喜爱、私聊开场、返回、悬停及提醒分别描述发生了什么、应关注谁；不预填应说的台词。用户互动与同伴互动继续沿用上一版的对象边界。
4. **有限示例**：从旧对白包中提取触摸、私聊开场、陪伴心情的示例。明确标为虚构语气参考，不是真实历史。每位最多两条，并排除与当前摸头／私聊开场直接对应的那类示例，减少就近照抄。同步软化了中英日示例中强行拒绝、收费和训话的表达。
5. **模型输出**：公共互动由模型产生 `beats`、动作、回应对象和可选 CG；单聊由模型生成文字，可调用形象工具。模型文字按原样展示，不在末尾拼接脚本，不用关键词删半句，也不把回应查表成固定模板。私聊明确携带当前输入，不要求模型对旧话题随意接一句。

运行时仍验证人物、动作、目标和 CG 权限；这是可执行输出的边界校验。即时摸头等本地物理反馈不等待网络，实际对白等待模型。API 失败或生成器缺失时显示错误，不降级成伪装为 AI 的脚本回复。

用户配置的定时提醒先准时显示系统通知；小屋空闲时，再请求模型以角色语气回应。正在对话、播放场景或 CG 时不抢占。离线演示与隐藏录制入口继续有本地台词，并标明来源。

## 验证与限制

144 项单元测试通过，新增覆盖七位角色／三种语言的有限示例、实际输入传递、模型输出不被模板替换、当前摸头模板不被直接提供、生成器缺失不回放本地文字，以及定时提醒不抢占忙碌对话。

隔离 SSE 端到端检查覆盖真实渲染器、IPC、provider 路径、接入失败及成功、摸头、投喂、私聊隔离与来源标识。

使用已保存的 DeepSeek 连接实测六次：Claude 连续两次摸头、GPT 摸头、DeepSeek 摸头、Claude 私聊开场和普通单聊。六次均由模型响应，无接口错误、无固定模板替换。本轮未出现“别碰掉书”等责怪式后半句，GPT 的克制和 DeepSeek 的活泼仍有区别。对话和密钥未提交仓库。

仍可看到 Claude 频繁提到书的惯性，且措辞受旧历史与模型本身影响；这次不宣称完全解决重复梗或穷尽所有情境。前一轮测试还误选了未在场的 GLM，等待超时；随后改为实际在场角色重新完成六项检查，不把那次超时记为 API 故障。

后续重点：由用户实际反馈评估“接住情绪、角色辨识、重复程度、无故纠正、动作与文字一致性”，再决定是否增加可编辑表达偏好、重生成和逐句反馈。避免通过不断加固定台词掩盖模型质量问题。

视频素材与窗口布局未改动。源码与本机桌面版更新到 0.5.0-alpha.8，公开 Release 单独发布。
