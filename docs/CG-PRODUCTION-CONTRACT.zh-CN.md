## 1. 本次文档审查结论

ACTING 已说明表演与用户视角；SUPPLEMENT 补了工具路线；PLAYBOOK 补了动机、节拍和钉板。可以保留。缺口不是更多提示词，而是以下可复核产物：

- 两张真正可执行的工单，包含素材角色、分镜、失败降级和等待/取消处理。
- 工具能力实证、统一验收与预算止损，避免把未跑过的工具叫成可靠产能。
- 片段、选择、关系事件之间的播放回执协议。引擎动作结束不等于所有视频真实播完。
- 素材版本、播放边界、许可/署名、公开发布状态的清单。

本轮已修正文档中 LivePortrait 生成递碗动作的越界描述、插件仓库错链、Seedance 版本兼容保证以及人设反差的过度绝对化。

也已审查新增的 [同人搜集与分流目录](FANWORK-PERSONA-AND-CG-CATALOG.zh-CN.md)：题材池可用，但「高频」「正典」缺逐字段证据，不能替代确认；缠尾与真正拥抱应归结构高风险 CG-B，持碗注视和递接易手须拆开估难度。下一步补逐条原页、可观看范围、时间码（若可播放）与采用字段。索引收录不等于人气排名。社区成片按目录仅学节拍，不直接入库；选定的自有 CG 分镜使用本项目已确认小屋背景，避免换成不相干场景。

## 2. 人设确认：必须分开四种依据

每一条身份卡字段记录 `value / evidence / scope / status`：

1. **已选视觉版本**：锚点文件、SHA256、作者/原页、画风/形态。Q 版和正常比例可以是同角色，但不能假定发饰、尾部连接和衣服天然一致。逐项注明映射；缺视角就标缺，不凑别家设计。
2. **项目运行人格**：`src/shared/characters.ts`、`social.ts` 中实际使用的设定；这是本项目解释，不是官方/社区统一定论。
3. **社区来源**：具体作品、作者和可访问范围，逐条关联到“哪一条设定”。只有标题不能证明某个眼神或尾巴动作。视频有可观看原片才记录时间码。
4. **本场演法**：例如“Claude 淡定、DeepSeek 害羞”仅绑定本工单。不能倒写成 DeepSeek 永远被动、Claude 永远不害羞。

冲突时先保住用户选定外形。叙事不能凭空加饰物：GLM 眼罩/铃铛按当前锚图逐项确认；Kimi 爱读书不等于每条待机都必须新画一本书。现有 `docs/animation-lab/character-consistency.json` 已明确相关限制，必须一起查。GPT 保留从身体尾根沿右侧下弯、底部收尖的同一条西方龙尾，不增独立尾尖；DeepSeek 是双叶鲸尾，两者不可混用。

身份卡至少包含：角色 ID、形态、锚图哈希、不可变特征、可变表情/动作、道具归属、尾根/尾尖示意、对用户与搭档的表达方式、三条禁漂移项、同情境差异台词、来源、待确认项。先由 agent 对照锚图验收，只有冲突或审美取舍才集中交给用户，不逐张重复要求确认。

**当前状态**：七人代码人格已存在；七份**草稿**身份卡已落在 [cg-production/identity/](cg-production/identity/README.zh-CN.md)（四层依据 + 待确认项），证据台账见 [evidence-ledger.json](cg-production/evidence-ledger.json)。仍缺逐视角锚图验收与三视图；本轮未批准新分镜，不得填 `approved`，不得恢复生成。

## 3. 工具能力与选择

官方核查日期同上：

- [Comfy Wan2.2](https://docs.comfy.org/tutorials/video/wan/wan2_2) 分别提供 I2V 与 FLF2V 模板。普通 I2V 首帧路线与首尾帧路线分开记录，不能只写“可选尾帧”而不保存对应工作流。
- [Fun Control](https://docs.comfy.org/tutorials/video/wan/wan2-2-fun-control) 消费控制视频，支持姿态、深度等；既有普通 I2V 的成功不证明这个流程本机已跑通。
- [Animate](https://docs.comfy.org/tutorials/video/wan/wan2-2-animate) 有 Move/Mix，官方模板有独立权重和预处理依赖。候选承担身体表演；本机双人接触未验收。
- [AdvancedLivePortrait](https://github.com/PowerHouseMan/ComfyUI-AdvancedLivePortrait) 用于面部表情编辑/动画候选，不负责手臂与碗的递接。二次元脸是否适合、双脸裁切合成是否露缝都待测。
- 即梦/豆包/其他云平台按账号当前界面记录：产品、模型原名、参考图角色、首尾帧兼容、分辨率/时长、预计消耗。`@` 参考不等于逐帧运动约束。没有实测前不声称云端一定优于本地。

已有 Wan FP8 V1 只证明该一次本地 I2V 试片可用。保留锁定环境；控制/表情实验另建环境，不更新原复现环境。恢复生成后，每次只比较一种新变量，保存 workflow、节点提交、权重哈希、种子、参数、耗时与失败原因。

**止损建议，待执行时记录实际值**：每个镜头最多两次同路线短试；同类结构错误连续两次则回分镜/控制轨，不继续堆提示词。云端仅用用户已授权的存量积分；运行前确认页面实际成本，不自动购买。正式比较至少用同一套单人表情、单人道具、双人无接触、双人接触四类题，不凭一条好片给模型排名。

## 4. 接入能力：现有与计划必须分清

现有：SceneDirector 的 Q 版作业按派发后报告的身体/移动结束时刻结算；缺席/必要步骤失败取消；CG V1 是 `manual-trial-only`，固定卡片，未接自动奖励。`CGMoment.tsx` 的 `onEnded` 目前用于片尾关闭，不是导演的成功回执。

尚未实现：头顶影片气泡、BEAT_WAIT/CHOICE_2 的跨片段状态机、视频成功回执、角色关系/用户亲密双轴独立偏好、七份身份卡驱动的素材选择。不要把文档代号当已有 API 或设置项。自动播放仍须额外验收，不能顺手打开 V1 自动标志。

### 4.1 后续播放状态契约

建议状态：`requested → preparing → playing → holding → awaiting-choice → playing-response → completed`；错误走 `failed`，Stop/DND/退场/关闭走 `cancelled`。WATCH 不经过选择阶段。状态只是实现规格，不是当前类型定义。

- 所有回执携带 `sessionId/jobId/segmentId/host`，引擎校验当前实例、片段和宿主。一次只认一个可见宿主；旧回执、重复回执和隐藏镜像不结算。
- 真实 `ended` 或已验收静帧模式的定时结束才算该片段成功；加载、入队、开始播放和达到预计秒数不能代替视频成功。超时只降级/失败，不当作完成。
- 用户选择由真实按钮事件提交一次；无回应默认安静结束，无奖励。选“先忙”是正常分支，不扣好感，也不继续催促。
- 邀请、等待、回应必须保持同一角色/道具连续性。停稳持碗后，下一段不能突然空手。尚无收尾片时，用静帧差分或 Q 版回应，明确降级。
- 奖励只在本工单规定的终态提交一次；跳过、取消、加载失败、对象退场都不伪造“共同完成”。WATCH 预览默认不奖励。
- Q 版动作和视频各有结束边界：未来媒体工单需要两者都成功，不能只借现有 `body.until` 宣称素材播完。现有完整手势队列可能晚于状态时刻，自动 CG 解锁前须补桥接验证。
- 失败/取消同时释放角色占用、暂停视频、移除等待按钮和点击区域；保留原先 Stop 不取消独立 Agent 任务的边界。

### 4.2 头顶气泡验收

先做无新视频的布局实现，复用 V1 手动片。双人先靠近，气泡锚在两人渲染坐标中点上方；用户向锚单角色。小屋 280–340px、桌面 300–360px 是初始目标，按可用区域缩放，不是硬编码验收常量。源画面 contain，不裁尾、头、手；边缘换位时不遮参与者脸和操作按钮。

测试：紧凑/常规窗口、不同缩放、左/右/顶部边缘、Dock/自由桌面、主/副屏、两人分离、空阵容、退场、DND、Stop、切换宿主。参与者不在同一宿主/显示器时不自动播放；不跨屏拉人。无新增窗口/黑幕/抢焦点。原生鼠标穿透与操作区域必须人工桌面复核，不用 Playwright 点击代替。布局失配则只留轻量提示或回到 Q 版，不强行遮屏。

## 5. 首批两张制作工单（草案，尚未批准生成）

### CP-001：Claude 给大鱼整理发饰

模式 WATCH，角色 rin/xia，SFW 正常比例；场景是两人关系演出，用户旁观。现有 V1 参考，V2 已废弃，不复用错误手臂尾帧。先定三张静帧：

1. Claude 看向鱼、略前倾；大鱼察觉；两人手均可追溯到各自肩肘。
2. Claude 的角色自身右手触已确认的鱼发饰，左手保留书；鱼两手留自己身侧。画面左右另标，不能把“右手”误当屏幕右侧。手若被挡，提供结构草图而非凭空补臂。
3. Claude 从容笑，鱼视线移开后偷看、轻红，鲸尾小幅收后停。结尾双臂/书/尾根连续。

唯一主动作是整理发饰。镜头固定，不同时环绕/拥抱/递物。先验证接触前后 2–3 秒，再组合。接触结构失败两次则退为靠近+视线差分，不把缺陷片导入运行素材。身份、静帧和工单都通过且用户恢复生成后才执行。

验收重点：四臂归属、唯一触点、手不穿脸、鱼与 Claude 表情不同步、鲸尾连接、连续结束。预览不奖励；未来关系事件需单独绑定真实播放与剧情成功。

### POV-001：大鱼给用户留饭

模式 BEAT_WAIT，单角色 xia，眼平镜头代表用户，不新增另一人的手。道具为同一个碗；先做发现/邀请、持碗等待、接过/稍后两个回应方案的静态分镜。

- 邀请：看向镜头，碗只向前轻推，不凭空易手。
- 等待：使用合格稳定末帧；选项“谢谢，我接过啦”/“先放着，我一会儿来”。不无限抖动、不强迫实时眼神追踪。
- 接过：若没有验收通过的碗离手过程，就保留碗并用语义合理的“好，我先替你放好”与开心表情；不能用台词掩盖画面瞬间消失。
- 稍后：温和放松，回 Q 版安静陪伴，不扣分；无回应超时同样安静退出。

LivePortrait 只可候选做头脸；递碗身体与道具走动作控制或静帧差分。实现状态机前可在审片页手动切换分镜，不声称产品已互动。记忆记录真实选择，不自动声称用户吃过饭。

## 6. 素材验收与入库

分四关记录 `pass/fail/not-run`，每关有检查者、日期和证据文件：

1. **身份与结构**：对锚图；逐帧检查接触、遮挡变换、尾部转向段；不能只抽三帧。多臂/断尾/换主是硬失败，不以画面漂亮抵消。
2. **表演与时间**：有可见动机、反应与停稳；全速及慢速看关节、眼神、尾巴。循环素材单独验首尾衔接；关系片默认一次，不靠倒放制造循环。
3. **交付画面**：CG 保留背景；透明 Q 版须真 alpha，在黑/白/彩底检查横条、边缘色溢、裁切和帧尺寸。修复前后都保留，不把抠像改变当原模型输出。对目标最小气泡尺寸检查脸部表情是否仍可辨。
4. **产品与发布**：解码失败、延迟播放、暂停、重复点击、跳过、退场、旧回执、取消、跨屏/缩放、离线兜底均有结果。核对作者/参考/模型/后处理及许可，不因代码 MIT 就推定美术可商业再分发；沿用现有 NOTICE 和 manifest 范围。

状态使用 `draft → identity-checked → storyboard-checked → trial → art-accepted → runtime-accepted`。公开再分发和自动播放是额外独立字段，不从 runtime-accepted 推导。参考 [工单模板](cg-production/work-order.template.json)，它是规划记录，不是应用可直接加载的 manifest。

每个版本保存父版本、原片哈希、参考图哈希、workflow/平台任务标识、运行参数、实际时长、裁切/alpha/锚点、过关证据、拒绝原因、署名、发布条件。正式接入时明确替换哪条旧动作；保留可回滚版本。不覆盖 V1 来隐藏 V2 失败。

## 7. 顺序与完成定义

1. 本轮三项 P2 修复验收：已通过，详见验收记录。
2. 下一轮先在现有手动试片上做头顶气泡、占用/取消与回执规格测试，不消耗生成额度。
3. 完成七份身份卡的证据与待确认清单，再完成 CP-001/POV-001 静态分镜规格。眼罩、道具、形态冲突集中解决。
4. 用户恢复生成后，再做最小控制实验；选路线依据同分镜质量/失败率/耗时，不依据参数量或平台宣传。
5. 每条通过艺术与运行双验收再加入实际菜单/事件；预览、用户关系、角色 CP 偏好与自动播放分别验收。不要扩大为七 Agent/浏览升级任务。
