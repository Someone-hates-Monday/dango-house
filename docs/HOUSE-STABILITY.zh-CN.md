# 窗口闪烁与动画恢复 · 0.5.0-alpha.6

## 已复现的原因

- MiniHouse 的 `now` 每秒更新；新消息时间戳比旧 `now` 更新时，气泡被当作未来消息暂时隐藏。上方空间因此反复请求 148→0→148，透明 Electron 窗口跟着重新合成。一次普通群聊实测发生 3 次 `setBounds`，高度为 448→300→448。
- 控制器还会为未改变的边界调用 `setBounds`，没有处理 Windows DPI 的约 1 DIP 舍入偏差。
- Claude 的 stoppedAt 将播放器置为暂停，但退出免打扰/停止后没有恢复通道；实测两次取样均停在 3.186 秒。
- 判断当前走路是否属于移动时，错误地读取了“最新姿态”。角色已经到位时该条件反而不成立，导致后续动作等待旧走路视频播完。
- 摸头、投喂及手动选片排在已有动作后面；DeepSeek 正常走路还会播放较长的恢复尾段。演示分享曾在投喂开始 2.8 秒后就切走。

## 修复

上方空间在启动、用户调整尺寸/位置时确定，空白区域继续鼠标穿透。对白出现、更新、过期，以及 CG 收起不再改变透明宿主尺寸；用户主动展开聊天和缩放仍可改变尺寸。新消息立即显示，不等待下一次秒级时钟。

控制器比较实际原生边界，仅在必要时调用 `setBounds`，并容忍 1 DIP 的舍入差异。拖动与房子位置保存保持原机制。

鼠标穿透也只在“进入/离开可交互区域”时切换；区域内连续移动鼠标不再重复调用原生 `setIgnoreMouseEvents`。稳定性脚本覆盖连续 30 次移动的去重检查。

Claude 显式接入 frozen 状态，退出免打扰/停止后恢复待机；以加载走路片时记录的 travel 状态判断退出，而非当前姿态。直接操作优先切入相应动画，其他正常动作仍按队列播放。DeepSeek 正常移动到位后通过既有快照过渡衔接动作；明确的 trip 演出没有改动。

DeepSeek 吃白饭保留至实际片长约 10.04 秒之后；分享等后续同角色动作依据当前 owned end 安排，避免提前切断。

## 验证与范围

134 项单元测试和生产构建通过。新增 `verify-house-stability.mjs`，使用隔离演示存档、真实 Electron 窗口和视频解码：连续对白不闪断、原生 resize 次数为 0，未改变的 layout 查询也不触发 resize；Claude DND 后时间从约 0.512 秒继续到 1.238 秒；多种直接动画、完整吃饭片段结束回待机、走路后动作衔接正常。

最终打包版检查通过：30 次区域内鼠标移动只改变原生穿透状态 1 次；走动、共享目的地、拖动、单份 CG 均正常。GPT 完整循环仍为 225 个解码时间戳，连续两轮通过。桌面快捷方式已更新并启动新版本。

此记录针对已经复现的软件原因，不宣称覆盖所有显卡/驱动的显示问题。未修改角色视频文件，未连接真实模型服务，也未重新生成素材。源码版本与本机应用为 `0.5.0-alpha.6`，公开 GitHub Release 仍需单独发布。
