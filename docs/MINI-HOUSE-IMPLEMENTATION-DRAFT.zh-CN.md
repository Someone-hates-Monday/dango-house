# 迷你小屋实现与验收 · 2026-11-15

状态：已在 `0.5.0-alpha.1` 源码实现。承接用户提出的“把她们放进迷你小屋，无聊时看看互动”和“小屋下方直接展开群聊”。下面保留设计依据，并区分当前实现与后续体验验证。

## 当前交付

- 主入口变为透明的小房子：爱心屋顶、屋檐挂件按钮、共享底座，保持图标配色。右屋檐依次是置顶、设置、收起；屋顶空白处可拖动，右下角调整大小并记住尺寸。
- 默认核心三人紧凑站位；其他角色可在高级设置加入。三人最小 320×280，五人以上最小 420×370；实际尺寸受屏幕工作区限制。调整尺寸不触发模型或行走；默认不巡游，靠近同伴只做小范围位置变化。
- 底座集中显示短句和群聊、摸摸、喜欢、投喂。角色不再用浮动长气泡遮住屋檐按钮。点击角色在下方展开私聊，群聊在相同位置切换。
- 设置与连接直接从小屋底部展开。测试成功才保存并启用 API 模式；空 Key 输入沿用已保存凭证，不删除。连接失败显示错误，不悄悄输出本地剧本。角色、关系、Agent 等高级设置仍有次级工作台。
- `HouseEvent → generateHousePlan → parseHousePlan → SceneDirector` 统一群聊、触摸、投喂、夸奖、私聊进入/返回、拜访与主动生活；私聊正文仍由独立角色上下文处理。模型输出有限的台词与动作意图，动作开关关闭时只执行 idle。公开实际发言及已完成事件进入共享上下文，私聊原文不进入小屋大脑。
- 主动生活请求上限每小时 6 次，允许不回应；小屋隐藏/免打扰时停止主动生成。停止、退场、改配置会使旧请求失效。用户明确互动单独计费，800ms 悬停延迟避免路过即请求。
- CG 由一个会话在房子上方播放一份；透明宿主向上扩展，小屋位置保持固定，聊天向下展开。顶端空间不足时折叠提示；用户可以收起或关闭。贴屏幕底部展开聊天需要向上避让，不能同时保证超出屏幕的聊天区仍显示。
- GPT 继续使用已验收的 `idle-subject-s1-clean-v3.webm`（225 帧）和 P1 摸头动画，没有新增素材或回退到错误龙女图集。

## 可重复验收

```powershell
npm test
npm run build
node scripts/verify-mini-house.mjs --packaged
node scripts/verify-house-ai.mjs --packaged
node scripts/verify-gpt-idle-loop.mjs --packaged --house
```

两个 mini/AI 脚本使用隔离 profile；AI 脚本启动本地 SSE 模拟服务，不使用或输出真实 Key。覆盖屋檐按钮可点击、三/七人、群聊/私聊、单份 CG、尺寸恢复、连接失败保持离线、成功自动启用、摸头投喂走模型、私聊隔离。GPT 脚本解码完整循环并检查帧数、尾帧、播放和停止后恢复。真实服务商连接结果另记验收记录，模拟通过不等于真实服务可达。

仍需用户体验验证：长期陪伴的有趣程度、台词个性、真实模型成本与延迟、不同 DPI 多屏手感。当前共享生活由一个小屋大脑生成多角色短回合，不声称每个角色是独立运行的 agent。

用户已认可这个收敛方向，并补充：小屋大小可调；人物更紧凑、少走动、以贴近相处为主；CG 位于小屋外正上方。以下尺寸为待验证的实现起点，不是固定限制。

## 产品使用方式

建议主形态是“住在桌面上的迷你合租小屋”。用户可以看她们相处，也能随时加入。桌宠/Dock 是这个共同生活空间的可选展示方式。

- 默认迷你小屋：只显示靠近相处的角色、少量家具、正在说的话和底部聊天入口。初始房间尺寸目标约 360×240，可由用户拖动边角调整宽高；真实尺寸需在用户屏幕与 DPI 下验证。
- 点击底部“聊聊”：在同一窗口下方展开历史与输入框，房间仍可见。小屋中的公开对白进入同一条群聊记录。
- 点击人物：选中她，在同一聊天区切换“和她悄悄聊”；可以一键回到群聊。私聊正文不自动广播给其他角色。
- 接入向导：选服务商、填 Key/模型、测试，成功后以一个“开始陪伴”动作保存并进入 API 模式。保留明确的离线演示入口。
- 关系、在场角色和连接配置放在次级设置。直接互动保留摸头、投喂、夸奖等，角色的动作库不占据主视图。

首个验证阵容使用 DeepSeek、Claude、GPT；其余角色保持可选。让三个人呈现不同性格、关注对象和记忆延续，比同时让七人逐个回复更容易判断体验。

## 紧凑布局、缩放与活动范围

- **可调的是可见小屋**：支持拖动边角改宽高，记住位置和尺寸；展开聊天只增加下方聊天区，收起后恢复原房间尺寸。人物保持比例与脚底锚点，适配房间可用空间。按实际屏幕工作区和 DPI 限制尺寸。
- **先聚在一起**：三人围在同一处小地毯/沙发旁，Claude 与 DeepSeek 可以相邻，GPT 靠近一侧；布局中心围绕角色安排，家具少而小。站位是初始构图，不锁死模型后续的关系选择。
- **少走动，有目的地动**：默认关闭无目的巡游；待机细节和自然表情继续播放，不做持续左右抖动。只有靠近某人、让位置、用户明确要求等事件才短距离移动；已足够靠近时直接进入后续互动，不播放原地跑步。
- **允许贴近与部分重叠**：沿用重叠不超过一半的要求，面部与可点击区域保持可辨识，优先用前后层次形成拥挤感。明确互动时允许靠肩等姿态，但不把两个角色长期完全叠在一起。
- **按实际人物轮廓摆放**：间距与边缘留白考虑尾巴、翅膀及视频透明边，不把 16:9 视频画布当作人物实体。缩小时不裁切肢体，也不为塞入更多人无限缩小；最小尺寸随在场人数和点击可读性决定。
- **站位稳定**：在人数变化、用户调整布局或事件需要时重新排位，不每帧执行互相推开的布局求解，避免拥挤时抖动、卡住和来回挤位。
- **缩放不算走路**：窗口大小变化只更新视图映射，不产生 walk 意图、不重播动画、不新开模型请求，也不改变聊天/演出会话。角色短途行走免去时，仍等待真实互动动作完成后再结算。

不能为紧凑站位拉伸角色、捏造缺失坐姿，或把 GPT 的正常视频换成其他图集。具体空间数值由真实素材和三人/多人实测确定。

## 小屋外上方的 CG

- 迷你形态将 CG 统一锚定在**可见小屋顶部中心外侧**，与屋顶留小间隙；画面和字幕不覆盖屋内人物或下方聊天。一个事件始终只有一份播放器，参与人数不改变份数。
- 默认 CG 宽度随小屋自适应，起点约为房间宽度的 80%，保持素材比例并限制最大尺寸。缩放小屋时同步重算，保持紧凑；不为播放短片自动放大房间。
- 播放前仍由实际互动、靠近与前置对白引入。视觉呈现为附着小屋的短片卡，不弹出带系统标题栏、任务栏项目或抢焦点的独立视频窗口。
- **实现必须跨出小屋的可见矩形**：当前普通 Electron 窗口外不能靠 `overflow:visible` 绘制。优先使用同一透明宿主容纳“小屋 + 上方 CG + 下方聊天”的边界并集，单独保存 `houseBounds`。CG 打开时宿主向上扩展，小屋屏幕位置保持不变；收起后恢复，不让小屋跳位置。额外透明区域需鼠标穿透。
- 若平台限制需要附着的透明辅窗，必须随小屋移动/缩放/最小化，隐藏任务栏项，不抢输入焦点；仍由单个会话持有播放权，视觉上保持附着，不成为另一个产品窗口。
- 屏幕顶部空间不足时先缩小到可读下限；仍放不下则收成屋顶边缘的可点开事件入口，不越出屏幕，不强行移到屋内或挪动用户摆好的小屋。保留关闭、收起和用户继续查看的选择。

## 实施前诊断：为什么仍像本地剧本（alpha.6 历史）

本轮只读检查发现，本机持久状态为 `mode=demo`、`provider=deepseek`、`model=deepseek-flash`。保存配置与启用 API 是分开的。当前可在设置中点击“一键启用真实聊天”启用普通模型聊天。

代码中，`send` / `private-send` 把 API 模式传入 `sequence`，已有模型回复和 `perform_action` 工具循环。其他入口仍使用本地路径：

- `pat` / `feed` / `hover`：直接调用台词帮助函数和 `perform`。
- `private-open`：使用固定欢迎与争宠规划。
- `praise`：调用 `sequence(praiseLines(...))`，没有启用其默认 false 的 `useApi`。
- `playSocial` / `playYuri`：把固定故事步骤排入导演队列。
- `companion-story`：既定步骤之外，模型仅补一句短旁白；该旁白不提供动作工具。
- 普通模型提示词已经包含手工记忆、关系熟悉度和最近聊天，但没有把完整的共同事件记忆作为统一生活上下文使用。

这些是实际调用链的缺口，不宜只靠修改提示词或把一个默认参数改成 true 来解决。

## 一次真正的互动

用户投喂 DeepSeek → 本地立刻播放已支持的投喂反馈 → 把“谁投喂了谁、食物、最近话题、在场角色、关系与可用动作”交给模型 → 模型决定回应、是否带上 Claude/GPT、对应动作意图 → 导演验证后按步骤执行 → 真正说出的话进入下方聊天记录 → 完成后记录实际发生的公共事件。

例子的情节种子可以是“DeepSeek 想分一点饭，Claude 靠过来，GPT 在旁边回应”。每次台词、参与人及具体举动根据当下生成；不把示例对白固化成轮播剧本。

人设、动画素材与执行约束保持稳定；模型负责当前说什么、想和谁互动、想做什么。程序负责动作是否存在、参与者是否在场、何时播放、是否取消、是否允许触发 CG。

## 实施顺序

1. **统一互动生成入口**：增加 `HouseEvent`（事件 ID、类型、发起者、目标、食物/内容、时间、可见范围）。聊天、触摸、投喂、私聊进入/返回和主动生活共用事件管线。纯机械动画无需请求模型。
2. **小屋导演**：一次有界请求规划少量角色的回应和动作。结构化输出只允许已知角色与可用动作；每次最多两三个发言/动作步骤，允许选择安静不回应。角色独立后端作为高级覆盖项保留，不默认让七位并行请求。
3. **复用现有 SceneDirector**：校验关系偏好、免打扰、在场、优先级、冷却和动作资源；沿用取消、完成回执与结算。过期模型回复不得在用户已切换话题/角色后继续执行。模型失败不伪装成本地 AI 回复。
4. **统一记录**：公开发言在实际执行时写入公共消息流；动作只记录确实发生的事件。气泡展示当前短句，底部保留聊天历史。角色私聊保持独立上下文。
5. **小屋内聊天**：从现有群聊抽出可复用的记录/输入组件，放到 Room 底部的可展开区域。原独立群聊入口跳转到这个区域。阅读旧记录时，新消息只提示，不强制滚动到底。
6. **迷你展示**：新增同一引擎的紧凑渲染视图，折叠/展开保持同一场景、聊天与会话；不能直接把当前最小宽度约 1000 的工作台缩小。多个窗口不得各自运行 AI 计时器、重复生成或重复播 CG。

## 主动生活与 CG

主动发言由“最近互动、未完话题、是否正在看小屋、安静/自然/热闹偏好”触发评估，允许不说话。设预算、冷却和短回合上限，用户离开或免打扰时停止主动生成。不要用几秒一次的固定台词、固定争宠和必出回复营造活跃。

CG 是当前关系互动的一个演出结果。模型可以表达场景意图；程序按真实参与者、关系模式、资源、冷却与用户偏好决定能否播放。迷你小屋按上节屋顶外侧锚点显示；空间不足则折叠为可点开的事件入口，不自行放大挡住桌面。

## 验收体验

- 在 API 模式，普通聊天、摸头、投喂和进入私聊的语言回应都真实请求模型；重复同一操作时，根据上下文产生变化。
- 用户能在一分钟内理解“看她们、加入群聊、找某个人私聊”。主视图不依赖说明书或演示按钮。
- 群聊内容能承接小屋实际发生的对话；第二次互动能用到上次发生的事情。
- 无 API 时明确处于演示；API 失败不输出伪装成生成结果的循环台词。
- 快速连续点击、改换对象、退场、免打扰和请求超时不会造成过期演出、重复请求、多人抢播或错误记忆。
- 拖动缩放和展开/收起聊天后，小屋位置与用户尺寸保持稳定；所有角色仍可辨识和点击，尾巴/翅膀完整，不触发原地跑步或新的模型调用。
- 三人紧凑相处时没有持续巡游、碰撞抖动或互相完全遮挡。切换人数与不同 DPI 后依旧成立。
- CG 在小屋外上方只显示一份；小屋移动/缩放时正确跟随，聊天焦点不丢失，透明空白不拦截桌面操作；靠屏幕顶边有可恢复的折叠行为。

这些是待验证的产品假设，尚不能断言所有用户都偏好这种形态。先用核心三人的“围观—加入—记得”闭环验证，再决定后续扩展。
