# 有目的地走动 · 0.5.0-alpha.5

此前 `room.wandering=false` 会抹掉所有移动目标，小屋渲染又固定使用站位并把 walk 姿态改成 idle；因此模型即使提出靠近，也只看到几像素的偏移。

## 当前行为

- 随意巡游仍默认关闭。有明确同伴、位置或坐标的移动继续执行；到位后留在新位置，直到下一次移动。切换人数会重新安排紧凑站位，重启时重新组成在场阵容。
- 小屋显示主进程的实际位置与路线，移动角色按帧更新；不再以一个 CSS 偏移冒充行走。缩放只重新映射场景，不触发模型或巡游。
- 已有 DeepSeek/Claude 走路素材接回移动阶段。GPT 等没有可靠配套走路片的角色仍使用已验收形象，平移时轻微起伏；不切回备用龙女，也不声称新生成了腿部动画。
- 模型通过 `target` / `replyTo` 指定靠近谁。缺少明确目标时，短回合最多让第一位相关同伴自动靠近，避免所有人不断换位。`stay:true` 使旁观者保持原位；形象动作开关关闭时不自动移动。
- 共同出发使用 `gather:{actors:["xia","rin"],target:"window"}`，支持窗边、地毯及已有家具 ID。各自寻找目的地附近的安全落点，不站到完全相同的点。到位后再开始台词。
- 移动途中不提前写入“已经到位”的台词；到达时才发言，队列后续步骤顺延。场景奖励和 CG 仍等待真实动作结束。嵌套的旧 model-reply 队列不会抢走整个小屋回合。

## 路线与空间

`house-navigation.ts` 提供统一投影、站位、身体重叠估计及有界网格寻路。当前与已预订路线均占用空间；允许靠近和部分遮挡，目标按约 44% 的身体矩形重叠限制规划，给缩放与渲染留余量。三/七人、多种房屋尺寸按 40ms 采样，重叠均未超过 50%。

小屋太挤或没有通路时，选择最近可达点，或保持原位做表情；不穿过同伴、不反复推开、不播放原地走路。把小屋调高或调宽可得到更多绕行空间。这是近似角色矩形的碰撞约束，不是逐像素身体轮廓碰撞。

## 验证

- 单元测试 133/133，生产构建通过。覆盖靠近、共同移动、到达后对白、取消不发旧台词、主动回合不被嵌套队列替换、旁观者不动、无目的 walk 的有界补全、关闭工具后不自动移动及多尺寸碰撞。
- `verify-house-movement.mjs` 使用隔离 profile 和本地 SSE 服务，检查实际画面坐标变化、不跳回站位、重叠、模型共同移动、到达后发言与 GPT 视频身份。
- 上述检查与 `verify-mini-house.mjs`、`verify-gpt-idle-loop.mjs --house` 的打包版验收通过；GPT 完整解码仍是 225 帧、两次循环，没有错误形象。
- 真实 DeepSeek `deepseek-flash`：请求两人到窗边、GPT 留在原处；模型返回 `gather`，DeepSeek 与 Claude 实际坐标均改变，GPT 未移动，整段演出正常完成。测试未读取或输出 Key。
