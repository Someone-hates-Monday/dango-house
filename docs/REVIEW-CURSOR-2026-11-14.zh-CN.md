## 结论

已达到能实际演示的多角色关系 CG 原型：会合/对话后播放、头顶定位、单人按实际演员判断、真实结束回执均可运行。还不是“所有聊天都能读懂情绪并选择 CG”的完整恋爱游戏。先前首发文档“只支持手动 WATCH”的快照已过时：Cursor 新增了部分事件完成后的自动播放映射。

本轮在当前未提交工作区验收，HEAD 仍为 35b3760。先读代码与跑原验证，发现问题后按用户新增要求直接修复；未推送、未发版，旧便携包没有自动更新。源码运行需重新启动以加载新构建。

## 发现并处理

- **GPT 当前仍路由到 S1 新待机**。用户再次报告错待机，本轮恢复到历史已接受的 Oct29 文件，校验 SHA256 `57fb864e…bda19`，用唯一新 URL `idle-reviewed-oct29-v2.webm`。public 里的新版/旧同名候选/备份共三份移至 `test-results/animation-lab/gpt/withdrawn-idles-2026-11-14/`，保留来源。不是只改 C1/C2 的实验区标记。无法仅凭源码确定用户当时看到哪一帧；现在可验证运行来源已切换。
- **GPT 防闪修复把动作冻结**：原有 special hold 分支让投喂/走动也显示暂停待机，实测投喂失败。保留循环解码就绪锁存，移除“所有动作都冻结”的特例，恢复正确图集动作兜底。
- **Claude 单人 CG 实际参与者仍写 xia**：移除 DeepSeek 后复测无法播放。本轮更正 catalogue 与素材 manifest 为 rin；旧文件 ID 保留以兼容，不误称大鱼单人。
- **单人片立即弹出**：现在同样先说话/做邀请，再播放；鱼主动靠肩明确由鱼发起，避免所有双人片永远 Claude 先走近。
- **偏好混在一起**：增加独立“女孩之间的贴贴”“互动后的剧情短片”设置并持久化；不以用户是否恋人决定她们能否亲近。用户向事件片要求恋人模式；手动预览依然可查看。关闭事件短片取消待处理邀请，已在播的自动片下一 tick 取消，不伪结算成功。
- **文案像调试面板**：移除部分 settle/工单编号/肢体制作说明；换成角色台词和自然入口。参与者标签替代 CG 卡片的工单 ID。英文核心 CG 文案同步调整；其他页面并未做全量本地化。

## 现在的触发规则

以下是明确事件绑定，不是对任意聊天进行情绪分类：

1. **Claude/GPT 收到“表达喜欢/夸奖”**：恋人模式、事件短片开启、对应角色在场，先播原喜爱反应，约 7 秒后进入专属邀请对白，再衔接对应单人 CG。Claude 邀请牵手，GPT 替你理额前碎发。朋友/宠物模式保留日常回应，不自动升格这两条恋爱片。
2. **窗边留座剧情完成**：对应窗边 CG；是剧情实际 settle 后进入，不是按钮点击就视为完成。
3. **rin-xia-seat 亲密小戏完成**：贴脸 CG；受“女孩之间的贴贴”控制。该设置关闭时不再派发这条百合小戏。
4. **两人拜访完成**：鱼靠肩 CG，受贴贴设置控制；分享饭食完成对应饭碗 CG。
5. **欢迎小剧场完成且 Claude、鱼在场**：恋人模式下对应“双人给用户留中间位”。不是每次启动、每次普通私聊返回都自动播放。
6. **手动片库**：明确点选短片；双人先会合，单人先邀请，不受自动播放开关限制。仍受在场、DND、专注等条件约束。

事件片全局间隔至少两分钟；手动试看片不受此间隔限制。摸一下不会每次都弹大 CG。事件片当前从小屋宿主播放；手动片可选桌面。后续如需“纯桌宠工作时事件也自动选桌面宿主”，须另做宿主偏好和活动窗口验证，不将现状宣传成已完成。

## 发布前剩余范围

### 补充：按全体参与者共用一个播放实例

单人锚本人，双人锚两人头顶中心，多人锚全体参与者头顶的平均中心。定位函数不再只取前两人；角色位置未齐时不降级成某一人的单人片。当前素材最多双人，多人定位由几何测试覆盖，不声称已制作三人同框影片。同一 renderer 的同一 session 只选一个可见播放器所有者，卸载时移交；小屋与桌面仍按同一会话宿主互斥。实机脚本新增卡片数量为 1、另一宿主为 0 的断言，四类 CG 通过。

针对用户确认的“小屋站立”：增强检查连续 23 秒采样得到 **115 个不同渲染画面**，跨两次循环；不是仅检查时间计数。另测主动暂停 idle video 后自动恢复，Stop 后新动作恢复也通过。为意外媒体暂停补了节流重播检查，尊重 DND/冻结状态；本次没有再替换或删减素材。当前最终单测 **113/113**，构建通过。

### 用户后续反馈：GPT 像单帧

进一步解码确认当前历史待机有 225 帧、225 个不同的 RGB 帧；不是单帧文件，但此计数本身不证明每帧身份或主观流畅度。上次选择了整段回退，未精确定位用户看到的错误画面，不能称已完成精准删帧。当前保留全部既有多帧动作，未进一步删正常帧。

找到并修复独立播放缺陷：P1 摸头中 Stop 会暂停视频，之后新动作虽然清除暂停标记，却没有恢复 `playing` 中的 video，tick 会持续提前返回而停在一帧。现在新动作会恢复尚未完成的反应。扩展原生 renderer 检查跨两轮待机后，再执行摸头→Stop→新动作，确认 currentTime 继续推进（`resumesAfterStop:true`）。112/112 单测与构建通过。用户具体出现单帧的位置仍待反馈，未将这条复现路径直接等同于所有现场情况。

不再扩角色与素材。用同一个候选包完成原生点击/遮挡、多屏缩放、无 Key 首次体验和一次真实 API 流程；检查发布清单确实纳入新图/片/配置与哈希，旧候选不再打包。固定三条拍摄路径：偏爱→回应、女孩贴贴、共同欢迎用户。新用户引导仍需实际录一次观察是否找得到入口；不要用按钮截图代替“新用户知道怎么玩”的验收。通过后再录宣传片、打公开测试标签。
