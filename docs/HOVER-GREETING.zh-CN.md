# 鼠标停留回应 · 0.5.0-alpha.9

## 为什么 GPT 看起来没有回应

旧逻辑会先写入悬停冷却，再检查 API 是否忙碌。忙碌或场景占用导致问候被丢弃后，该角色仍可能被锁住 90 秒。悬停还被“主动聊天”总开关一并禁止。

GPT 目前只有已验收的待机与摸头视频。保护形象一致性的播放器不会因模型输出 `wave` 就切回旧图集；因此等待模型或处于冷却时，也看不到其他角色那种挥手变化。这次不以重新启用旧立绘解决问题。

## 新行为

- 小屋停留约 800 ms、自由桌宠约 600 ms 后，显示一次很轻的整体点头与名字高亮。移开再停留可再次回应；这是现有视频表面的轻微过渡，不是新增挥手或视线追踪视频。
- 视觉回应不等待 API，也不受口头问候冷却限制。动画只播放一遍，不持续晃动；系统减少动态效果时关闭点头动画。
- 用户悬停是主动输入，与自动闲聊分开。关闭主动聊天后仍可悬停互动。免打扰时取消尚未到时的停留，并不显示新回应。
- 小屋忙碌、已有场景或播放 CG 时不抢话，也不消耗问候冷却。移开、待空闲后再次停留即可请求问候。API 失败也不消耗 90 秒冷却。
- 成功的口头问候仍保留每位 90 秒、全局 15 秒的频率限制，避免鼠标来回经过时反复调用 API。静音、未在场或专注中的角色不发起口头问候。
- 短暂划过、开始点击或拖动、移开、窗口失去焦点时取消未完成的停留。移动中的小屋／自由桌宠不触发新点头。Dock 保留原本靠近后站起的反馈，共享修正后的问候触发规则。

## 验证

148 项单元测试与生产构建通过。新增测试覆盖关闭自动聊天后 GPT 仍能回应、忙碌／队列／CG 不误计冷却、API 失败后可重试，以及免打扰、静音、缺席和专注限制。

`scripts/verify-hover-greeting.mjs` 使用隔离存档、真实鼠标停留、IPC 和延迟的本地 SSE 服务，验证快速划过与 DND 取消、先视觉后模型回复、冷却期间仍有视觉反馈、动画仅播放一次，以及 GPT 始终使用正确待机视频且无旧图集备用层。

保存的 DeepSeek 连接也通过真实鼠标停留获得一条 GPT 模型问候，无 API 错误。此前一次重复启动测试因用户已打开应用、同一存档缓存占用而退出；关闭已确认路径的旧应用后复测成功。未读取或导出密钥，未将实际对话入库。

此版本不修改视频素材或原生窗口尺寸机制。源码、本机应用与快捷方式更新到 0.5.0-alpha.9；公开 Release 另行发布。
