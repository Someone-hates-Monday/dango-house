## Adjacent products

These are current first-party README/documentation claims, not hands-on competitor reviews:

- [dsh-pet](https://github.com/PC2005-cloud/dsh-pet): transparent animated pets, multiple instances and DIY video assets; also an upstream source for our DeepSeek art. Learn the short installation-to-result path and retain attribution.
- [CrossPet](https://github.com/lokicorvus/crosspet): AI-client/work-state integration, now also multiple pets, friendship and idle exchanges. Multi-character interaction is no longer a sufficient differentiator.
- [N.E.K.O.](https://github.com/Project-N-E-K-O/N.E.K.O): voice/vision, memory, visits, community and plugins. Relationship-first positioning alone is not exclusive.
- [Open-LLM-VTuber](https://github.com/Open-LLM-VTuber/Open-LLM-VTuber): voice/vision, Live2D and extensible local/cloud models. Do not frame unfinished voice or agent features as our launch advantage.
- [SillyTavern groups](https://docs.sillytavern.app/usage/core-concepts/groupchats/): character cards, shared history and reply strategies. Group chat/personas alone are established capabilities.

Our proposed distinction is the concrete combination of **desktop attention rivalry, gentle girl–girl romance, affection toward the user, bounded CG scenes and a cute Dock home**. Demonstrate it; do not claim first/only or infer virality from repository popularity.

## Message and audience

Keep **Dango House / 团子小屋**. Core line: **“They like you—and have someone they want to get closer to.”**

Describe a desktop AI-girl home with romantic roleplay, gentle yuri and companionship. Show three paths: attention changes reactions; pair/solo/shared-user affection; everyday Dock/room interaction. Agent bridge and model configuration are supporting features. Explain single-key persona mode honestly. A freeform API conversation and an offline scripted scene need different labels.

## Main trailer: 45 seconds

0–3s: Dock selection and a visible reaction. 3–10s: three distinct responses to favoritism. 10–18s: pair cuddle CG with the actual in-app playback entry visible. 18–25s: solo invitation and both women welcoming the user. 25–32s: petting, feeding, Dock and room. 32–39s: cast/relationship/backend settings and a verified bridge connection. 39–45s: product name, Windows public alpha and one download CTA.

Label CG as in-app manually selected scenes. Do not imply automatic triggering or live generation. Keep reaction holds and normal animation speed; fast cuts belong to feature transitions. Produce separate language editions.

Cut three distinct short trailers: attention rivalry, pair romance, and shared-user affection. Test comparable lengths using available retention, saves, download clicks and voluntary onboarding feedback. Do not promise viral metrics or spam duplicate cuts.

## Bounded prelaunch pass

Verify one package from a clean profile: offline demo, API, stop/close, relationship cancellation and return, all eight CGs in room/desktop, scaling, overlays and physical mouse hit testing. Use that exact package for recording and downloads.

Two concrete issues to resolve: `cg-preview` currently requires both rin/xia even for solo GPT media; eligibility and cancellation must use the real cast per clip. Also `xia-reach-t1` names xia in metadata while its art description/work order names Claude. Inspect actual video, then reconcile IDs/cast/menu; explicitly map asset name gpt to runtime shiori. These are release fixes, not reasons to add automatic CG before launch.

Align version, changelog, screenshots, download and installation guide. Preserve art/source/music terms separately from code MIT. Final full-package runtime acceptance remains outstanding.

## Release sequence

Freeze RC after debugging, have a few new users try download/start, then publish the Windows alpha with a Bilibili trailer, the same GitHub package, bilingual README and a short install guide. Recut vertical editions for other platforms. Follow with one relationship short and Q&A, then fixes based on actual reports. Developer bridge tutorials and contribution guides are the second wave.

One main CTA: **download and try**. Put stars, contributions and issue feedback in the repository/description. Track the usable path from download to first interaction and returning interest, rather than views alone.
