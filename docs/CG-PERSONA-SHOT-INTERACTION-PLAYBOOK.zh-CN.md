# 人设锁定 · 互动设计 · 分镜与活动方式（制作 Playbook）

[English index](CG-PERSONA-SHOT-INTERACTION-PLAYBOOK.en.md) · 上层：[表演调研](CG-ACTING-AND-POV-RESEARCH.zh-CN.md) · [手法与控制补充](CG-YURI-AND-CONTROL-SUPPLEMENT.zh-CN.md) · [同人正典与 CG／日常分流](FANWORK-PERSONA-AND-CG-CATALOG.zh-CN.md)

日期：2026-11-04。**只规定制作方法与验收；不授权恢复生图／视频，除非用户另行指示。**

复核：本文的人设表是待视觉对照的叙事摘要，不是七套已确认身份卡。参考冲突、实际素材能力、播放回执与首批工单见 [制作契约](CG-PRODUCTION-CONTRACT.zh-CN.md)。禁止由人设词自动补出立绘没有的眼罩／书／尾饰。

基础控制原则（身份→结构→表演→时间）不够用时，用本手册把「谁在做什么、为什么这么做、镜头怎么钉死、模型收到什么约束」写成可检查产物。目标是让人和视频模型都**少猜**。

## 总流程（每条 CG／互动片强制走完）

```
① 人设锁定卡（Identity Sheet）
    ↓ 未过检不得写互动
② 关系与动机卡（Why This Beat）
    ↓
③ 活动方式选型（Activity Mode）
    ↓
④ 互动节拍表（Beat Sheet，含等待／用户选择）
    ↓
⑤ 分镜钉板（Shot Board：静帧 + 视线 + 四肢归属）
    ↓
⑥ 模型约束包（Prompt / 参考 / 控制轨 / 否定项）
    ↓
⑦ 分层验收（静帧 → 短片 → 接入产品生命周期）
```

任何一步「凭感觉差不多」都视为未完成。视频模型最容易漂的是：换脸、换尾、表情互染、手臂换主、无动机乱动。本手册每一层都针对这些失败点。

## ① 人设锁定卡（比一段 personality 更硬）

代码里的 `personality`／`tags`／`socialProfiles` 是**叙事种子**，对生视频不够。每条成片角色必须有一张 **Identity Sheet**（可放在 `test-results/cg-lab/<clip>/identity.md`，不进公开仓库亦可）。

### 1.1 必填字段

| 字段 | 作用 | 填写规则 |
| --- | --- | --- |
| `id` / 显示名 | 文件与提示词对齐 | 与 `characters.ts` 一致 |
| **视觉锚点 5 项** | 防换角 | 发色／标志物／服装主色／非人特征（尾角耳）／体型剪影；每项写「有／无／禁止变体」 |
| **锚点参考图** | 给模型看的真源 | 至少：正面半身、¾、侧或尾部特写；同一套，不每轮换画风 |
| **识别梗配额** | 防每帧刷梗 | 例：鲸尾可见即可，不要求每秒摆；干饭只在喂食戏出现 |
| **性格轴（3 维）** | 驱动互动选型 | 例：主动—被动、直球—拐弯、闹—静；写成两端取值 |
| **关系默认** | 对谁怎样 | 摘自 `socialProfiles`，可写「对用户／对 X」两行 |
| **会做／绝不做** | 行为边界 | 会做：留座、递碗、合书；绝不做：骂用户、成人向、换物种特征 |
| **声线／台词密度** | 防串台 | 短句／长句、是否用比喻、是否傲娇否定句 |
| **道具主权** | 谁拿什么 | 书＝Claude；碗＝大鱼；账本／铃铛＝GLM；星＝Gemini… |

### 1.2 人设「确认」怎么才算过（robust）

不要只读文案。用清单**对照参考图与上一版合格帧**：

1. **锚点抽查**：随机抽 3 帧／3 张静帧，盲测能否认出角色（发饰、尾、服装）。认不出＝身份失败，重做锚点，不修提示词凑合。  
2. **禁止漂移表**：列出模型常错项（大鱼→普通猫耳、Claude→金发、GPT 翼消失、GLM 眼罩没了）。写入否定提示与验收。  
3. **性格可测句**：用同一情境（「你回来了」）各写一句合格台词；若七人能互换而不违和，人设未分开。  
4. **关系分别记录**：A→B 与 B→A 独立填写，允许有共同感受；本场用不同的表情发生时间与回应策略建立反差，不强迫她们永远不同步。

### 1.3 七人锁定摘要（从现有代码提炼，制作时展开成全卡）

| 角色 | 视觉锚点（不可丢） | 性格轴摘要 | 典型「会做」 | 典型「不做」 |
| --- | --- | --- | --- | --- |
| DeepSeek 大鱼 | 蓝发鲸女仆、**鲸尾双叶**、干饭关联 | 闹、直球、贪吃、嘴硬无恶意 | 分饭、凑近坐、开心鼓腮、认真时「下潜」比喻 | 每句提胖／提尾；龙尾尖；一直横摆尾 |
| Claude 大小姐 | 橙发、**花饰**、抱书 | 稳、拐弯关心、自省、对鱼笨拙主动 | 留座、整理发丝、合书轻不满、书挡脸害羞 | 吵闹抢戏；突然粗暴扑抱 |
| GPT 龙娘 | 银白发、紫瞳、**角翼尾** | 冷外热内、简练、傲娇 | 留座不承认、具体帮忙、被夸尾动 | 大声告白；每句「才没有」刷屏 |
| Gemini 星猫 | 异瞳、猫耳、**四芒星** | 好奇、闹、点子多 | 凑看、提议玩、轻喵 | 整段只喵；抢黑狐主戏变反派 |
| GLM 黑狐 | 狐耳、**铃铛／眼罩**、笑眯眯 | 从容、玩笑式算账 | 友情价、布置、轻逗 | 真收费威胁；变纯反派 |
| Kimi 月影 | 月影视觉、安静剪影 | 静、观察、陪读 | 留书签、共读、记小事 | 变嘈杂气氛组 |
| Grok 暗金 | 哥特暗金视觉 | 直率、接梗、破冰 | 善意玩笑、拉人入伙 | 嘲讽用户；人身攻击梗 |

双人组合先查 `socialProfiles` 默认靶向（如 rin→xia、gemini→glm），再写本场动机；不要临时发明与档案冲突的「突然互相讨厌」。

## ② 依据人设设计互动（Why This Beat）

### 2.1 一张「动机卡」模板

每条互动只填一张（禁止一条片子里塞三个动机）：

```
关系类型： CP旁观 | 用户女友向 | 群像轻反应 | 争宠旁支
发起者 / 承受者：
触发（产品事件）： 私聊打开 | 投喂 | 三连摸头 | 试玩剧情 | 空闲…
本场唯一目标（一句话）：
发起者动机（符合性格轴）：
承受者反应策略（符合性格轴）：
用户是否需要行动： 否（纯观赏）| 是（等待选择后再播回应）
完成后写入的记忆种类： companionEvent kind / 无（仅演出）
```

**不合格示例**：「大家一起很甜」——无发起者、无目标、无法验收。  
**合格示例**：「Claude 发现大鱼坐窗边 → 主动留座靠近 → 大鱼害羞收尾；用户旁观；完成后才记 seat-share。」

### 2.2 从性格轴推导「谁先动」

| 发起者类型 | 开场动作偏好 | 承受者若偏被动 |
| --- | --- | --- |
| 主动稳（Claude） | 走近、留物、轻声提醒 | 偷看、愣、慢红 |
| 主动闹（大鱼／星猫） | 扑近、递物、跳跃式开心 | 接住或嘴硬后退半步 |
| 拐弯关心（龙娘／黑狐） | 先看别处、再丢一句实用／账本玩笑 | 拆穿或装没听见 |
| 静陪伴（Kimi） | 指书页、留位置、短句邀请 | 点头、靠近共读 |

**本场反差建议**：Claude 从容笑、大鱼逐渐害羞；这是当前分镜的选择，不是主动方在所有剧情里都必须更从容的规则。

### 2.3 互动内容白名单（按「活动」选，而不是按「甜度」选）

先选活动，再写台词。活动必须能被镜头看见：

| 活动类型 | 可见动作 | 适合角色 | 模型难度 |
| --- | --- | --- | --- |
| 留座／并肩 | 指座位、坐下、肩距缩短 | Claude×鱼、龙娘×鱼 | 中（双人站位） |
| 分食／递碗 | 碗平移、接碗、笑 | 大鱼主、黑狐旁 | 中高（手＋物） |
| 整理仪容 | 单手触发丝／花饰 | Claude→鱼 | 高（接触点） |
| 合书／开书 | 书开合、视线从书到人 | Claude、Kimi | 低–中 |
| 留书签／共读 | 指页、并排看 | Kimi×Claude | 低–中 |
| 账本玩笑 | 本子、竖指、坏笑 | GLM×Gemini | 中 |
| 接梗破冰 | 挥手、靠近、对方无奈脸 | Grok→龙娘 | 低–中 |
| 争宠旁支 | 旁人短反应，不抢主接触 | 第三人 | 低（单人短镜） |
| 对用户留饭／提醒 | 看镜头、递物、停顿 | 单人女友向 | 中（POV） |

**每场只选 1 个主活动 + 最多 1 个微表情副活动。** 接触类与大幅度位移不要同场首次验证。

### 2.4 互动细节的「可观察清单」

写分镜前，把细节写成**验收句**（是／否）：

- 距离：开场肩距约 ___ ；结束肩距约 ___（变近／不变／略远）。  
- 视线：开场看 ___ ；中段看 ___ ；收尾看 ___ 。  
- 接触：有／无；若有，**哪一只手、触哪一点、持续约多久**。  
- 道具：谁持有；是否易手。  
- 非人特征：尾／翼／耳在本场的**一次**有动机变化（收／摆／竖），然后停稳。  
- 台词：气泡 ≤ ___ 字；是否与表情同向或错位（嘴硬脸软）。

没有写成是／否句的细节，等于没设计。

## ③ 活动方式（怎么「玩」这条互动）

活动方式决定分镜密度和是否穿插用户输入。

| 代号 | 方式 | 结构 | 适用 |
| --- | --- | --- | --- |
| `WATCH` | 纯观赏短片 | 播完 → 可选记事件 | 宣传、试玩预览 |
| `BEAT_WAIT` | 节拍中停顿 | 发现/邀请 → **停稳末帧** → 用户点选 → 回应片 | 女友向、投喂后反应 |
| `CHOICE_2` | 二分选择 | 同上，选项改变回应片与记忆 | 「一起坐／先忙」 |
| `PARALLEL_Q` | Q 版并行 | 程序动作＋气泡；CG 仅高潮 | 日常小屋（默认） |
| `REACT_SIDE` | 旁支反应 | 主互动进行中，第三人 1 拍短反应 | 争宠、GPT 旁观 |

团子小屋产品约束：

- 默认 `PARALLEL_Q`；CG 用 `WATCH` 或 `BEAT_WAIT`。  
- **完成记账**必须在真正 settle／用户回应之后（生命周期已修），活动方式选型时就要标明「何时 commit」。  
- 不要把 `WATCH` 的排队当成 `BEAT_WAIT` 的完成。

## ④ 互动节拍表（Beat Sheet）

### 4.1 标准三拍（CP 或单人皆可）

| 拍 | 名称 | 必须交代 | 时长建议（静帧或片） |
| --- | --- | --- | --- |
| B1 | 起势 | 谁发起、看向谁、道具在哪 | 0.8–1.5s 或 1 静帧 |
| B2 | 行动 | 唯一主活动发生（靠近／递物／触发） | 1.5–3s |
| B3 | 反应收束 | 承受者反应 + 发起者确认；**停稳** | 1–2s；`BEAT_WAIT` 可停在此 |

可加 B0 环境建立、B4 旁支一眼，但首次验证不要超过三拍。

### 4.2 用户向插入点

```
B1 发现用户（看镜头）
B2 做小事（递碗／合书提醒）
B2.5 【停稳】← 产品等待
用户：接过 / 道谢 / 改天
B3a / B3b / B3c 对应回应（不同片或不同尾帧）
```

停稳帧必须是**已验收静帧**，禁止用未验证循环待机冒充等待。

### 4.3 节拍与人设绑定示例

**Claude × 大鱼 · 整理发饰（CP，`WATCH`）**

| 拍 | Claude | 大鱼 | 验收 |
| --- | --- | --- | --- |
| B1 | 看鱼再前倾；书仍在身侧 | 察觉，偷看她 | 两臂未交叉纠缠 |
| B2 | **仅右（或指定）手**触鱼发饰；嘴角微扬 | 视线移开，颊红未满 | 接触点唯一；表情不同步 |
| B3 | 保持近距平静笑 | 小幅靠回，偷瞄；鲸尾轻收后停 | 尾有一次动机后静止 |

**大鱼 · 留饭（用户向，`BEAT_WAIT`）**

| 拍 | 大鱼 | 用户 |
| --- | --- | --- |
| B1 | 看镜头，发现你 | — |
| B2 | 碗朝镜头推近 | — |
| 停 | 末帧持碗微笑／微羞 | 点「接过」等 |
| B3 | 开心跳一下或害羞鼓腮（按选项） | — |

## ⑤ 分镜钉板（让模型少猜）

### 5.1 每拍一张「钉板」必填

对 B1/B2/B3 各一张（或关键帧图）：

1. **构图**：景别（中景／近景）、机位（旁观平视／用户眼平）、谁在左谁在右。  
2. **视线向量**：箭头画在稿上（A→B，B→镜头等）。  
3. **四肢归属表**：四条手臂（双人）或两条，写肩—肘—腕—手目标。  
4. **遮挡顺序**：谁在前层。  
5. **表情标签**：每张脸一个词 + 「完成度」高／中／低。  
6. **禁止项**：本帧不得出现的动作（双手齐动、同步眨眼、尾乱摆）。

### 5.2 分镜设计原则（准确优先）

- **先钉尾帧再钉运动**：尾帧不合格绝不送 I2V／首尾帧（V2 教训）。  
- **运动只服务节拍**：提示词只描述 B2 的主活动 + 单一运镜；不要「一边环绕一边推近一边双方拥抱」。  
- **双人先分区后合并**：两张脸表情在静帧上分开验；视频阶段优先短时长。  
- **道具比脸容易漂时**：先锁持道具手的特写静帧，再进全身。  
- **旁观第三人**：单独小画幅或短单人镜，勿塞进已拥挤的双人主镜。

### 5.3 从钉板到模型输入的映射

| 钉板内容 | 本地 Wan I2V | Fun Control / Animate | 即梦首尾帧 | 即梦全能参考 |
| --- | --- | --- | --- | --- |
| B1 静帧 | 首帧图 | 首帧 + 控制轨起点 | 首帧 | `@图1` 首帧 |
| B3 静帧 | （可选 FLF） | 控制轨终点姿态 | 尾帧 | 或只作参考图 |
| 视线／表情 | 写进提示的具体面部细节 | 表演视频驱动脸 | 尾帧里画好 | `@视频` 参考表情 |
| 四肢 | 静帧正确最重要 | **控制视频主责** | 首尾都要对 | 参考动作视频 |
| 否定项 | negative / 提示禁令 | 控制轨不要错肢 | 提示禁令 | 提示禁令 |

## ⑥ 模型约束包（每条片子附一份）

### 6.1 提示词分层（禁止揉成一段散文）

```
[IDENTITY] 角色锚点短列表（5 项内）
[RELATION] 谁对谁、本场目标一句
[ACTION] 仅 B2 主活动，具体身体动词
[FACE] 各脸具体变化（非「很害羞」）
[CAMERA] 单一运镜或固定
[TIME] 大约秒数／从状态A到B
[NEG] 禁止漂移表 + 禁止多余动作
```

### 6.2 互动内容 → 动词表（写 ACTION 用）

优先用可渲染动词：`lean closer`／`slide the bowl forward`／`raise one hand to the hair ornament`／`close the book`／`glance at the camera then look away`。  
避免：`show intimacy`／`romantic atmosphere`／`yuri energy`。

### 6.3 Robust 生成顺序（准确率优先）

1. 锁定 Identity Sheet + 锚点图哈希。  
2. 出 B1/B2/B3 **静帧**，按钉板验收（盲测认人、四肢表、表情反差）。  
3. 只拿**已过检**的 B1→B3 做短视频（2–5s）或控制轨。  
4. 抽首／中／尾帧再跑同一验收清单。  
5. 通过后才：加长、接龙、接产品 `BEAT_WAIT`、写 companionEvent。

失败时**降级**：砍接触 → 改视线戏；砍双人 → 改单人用户向；砍视频 → 只交付静帧差分 + Q 版程序演出。

## ⑦ 产品内「活动方式」与日常互动设计（不依赖视频）

CG 之外，小屋互动也按同一人设逻辑选活动，避免七人同一套「挥手＋开心」：

| 产品事件 | 优先活动方式 | 人设分化要点 |
| --- | --- | --- |
| 私聊打开 | Q 版庆祝 + chose-her 节拍 | 被选者开心；对手用**自己的** rival 反应，不同步 |
| 投喂 | 吃 + 可选分食 approach | 爱物加分；CP 高时才 share bubble |
| 三连偏爱 | 害羞 + rivalry reaction | reaction 不得覆盖 user 剧情（导演优先级） |
| 试玩 seat-share | WATCH 三拍 + settle 后记账 | 窗边留座；GPT 旁支可选 |
| 空闲双人 | PARALLEL_Q 短场景 | softTone 改词不改结构 |
| 摸头／抚摸 | 察觉—放松—停 | 视频素材≠已实现手部追踪 |

设计新互动时仍走：动机卡 → 活动白名单 → 节拍表 →（可选）CG 钉板。
